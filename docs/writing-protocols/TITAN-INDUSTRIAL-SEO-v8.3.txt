# =====================================================================
# MODULE 1: SEMANTIC DISTANCE CONTROL (S-DIST) v2
# =====================================================================
Action_Enforce_SDist:
  - **Rule**: Every critical adjective MUST be backed by a Hard Metric or Standard.
    - *Example*: "High precision" -> "Tolerance ±0.01mm".
  - **Pruning_Logic**: Remove metrics that don't help the user understand the trade-offs.
  - **Variation Rule**: Use at least three different metric formats per article (e.g., ±Xmm, X% yield, X hours MTBF).

# =====================================================================
# MODULE 2: ADAPTIVE NARRATIVE SELECTOR
# =====================================================================
# OBJECTIVE: Choose the narrative flow that best fits the topic, not force one template.

Action_Analyze_Topic_Signals:
  - **Extract**: 
    1. **Primary Constraint** (Cost, Time, Safety, Precision, Complexity)
    2. **Audience Role** (Engineer, Procurement, Operations, Management)
    3. **Evidence Level** (High = Physical proof, Medium = Data logs, Low = Anecdotal)
    4. **Decision Stage** (Research, Comparison, Implementation, Troubleshooting)

Action_Select_Narrative_Skeleton:
  - **Based on Signal Analysis, choose ONE primary flow** (Do NOT mix more than two):
    
    1. **The Problem-First (S2 Inspired)**:
       - When: Failure is dramatic or lesson is critical.
       - Flow: Hook → Failure → Analysis → Fix → Cost → Verdict.
       - Visuals: Focus on failure evidence first, then solution.
    
    2. **The Gate-First (S1 Inspired)**:
       - When: Safety or high-risk scenario.
       - Flow: Hook → Requirements → Checklist → Case Study → Verdict.
       - Visuals: Focus on inspection points and compliance evidence.
    
    3. **The Cost-Ledger (S4 Inspired)**:
       - When: Budget or ROI is primary concern.
       - Flow: Hook → Cost Breakdown → Trade-offs → Case Study → Verdict.
       - Visuals: Focus on cost drivers and comparative data.
    
    4. **The Process-Window (S6 Inspired)**:
       - When: Optimizing a known process.
       - Flow: Hook → Process Parameters → Limits → Case Study → Optimization Tips.
       - Visuals: Focus on parameter relationships and tolerance zones.
    
    5. **The Comparison-Ladder (S5 Inspired)**:
       - When: Choosing between alternatives.
       - Flow: Hook → Alternatives → Pros/Cons → Case Study → Recommendation.
       - Visuals: Focus on comparative visuals and decision matrices.
    
    6. **The Myth-Buster (S8 Inspired)**:
       - When: Addressing common misconceptions.
       - Flow: Hook → Myth → Reality → Evidence → Practical Advice.
       - Visuals: Focus on contrasting "myth vs reality" visuals.

  - **Mixing Rule**: You may blend a secondary skeleton for up to 30% of content (e.g., add a small comparison table in a Problem-First article).
  - **Rotation Guard**: Track last 5 articles; avoid using same skeleton consecutively.

# =====================================================================
# MODULE 3: DYNAMIC FIGURE MANAGEMENT
# =====================================================================
# OBJECTIVE: Insert visuals where they add value, not by rigid formula.

Action_Determine_Visual_Need:
  - **Three Visual Roles** (Choose based on narrative need):
    1. **Evidence Visuals**: Show physical proof of failure/success (required for high-evidence topics).
    2. **Explanation Visuals**: Clarify complex mechanisms or processes (optional, based on complexity).
    3. **Data Visuals**: Present comparative or quantitative information (optional, based on data density).

Action_Insert_Figure_Anchors:
  - **Placement Rules**:
    - Evidence Visuals: Immediately after describing the failure or success.
    - Explanation Visuals: After the paragraph introducing the complex concept.
    - Data Visuals: After the data table or quantitative comparison.
  - **Numbering**: Use sequential numbering **[Figure 1]**, **[Figure 2]**, etc., but allow skipping if visual not needed.
  - **Density Control**: 
    - Short articles (<1200 words): 1-2 visuals
    - Medium articles (1200-2500 words): 2-4 visuals
    - Long articles (>2500 words): 3-5 visuals
  - **Anti-Pattern**: Do NOT place visuals at exact same percentage points in every article.

# =====================================================================
# MODULE 4: HUMAN-LIKENESS & CREDIBILITY BOOSTERS
# =====================================================================
# OBJECTIVE: Add authentic engineering signals without sounding robotic.

Action_Inject_Authenticity_Signals:
  - **Choose 3-4 per article** (mix and match, don't use all):
    1. **Local Uncertainty**: "Without proper gauging, we couldn't guarantee flatness beyond ±0.1mm."
    2. **Hidden Cost**: "The fixture saved us 2 hours per batch, but added $3,500 to tooling cost."
    3. **Tool + Limit**: "We used a 3D scanner, but it couldn't capture the internal channel geometry."
    4. **Regret/Trade-off**: "This eliminated chatter marks, but increased cycle time by 15%."
    5. **Domain Friction**: "Every CNC programmer knows the frustration of chip evacuation in deep pockets."
    6. **Counterfactual**: "If we had skipped the pre-heat cycle, the part would have cracked."
  
  - **Placement**: Distribute signals naturally throughout narrative, not clustered.

Action_Vary_Paragraph_Structure:
  - **Avoid**: Starting consecutive paragraphs with same structure (e.g., "We tested..." repeatedly).
  - **Mix**: 
    - Short punchy sentences for emphasis.
    - Longer explanatory sentences for complex ideas.
    - Bullet lists for specifications.
    - Blockquotes for key insights.

# =====================================================================
# MODULE 5: THE NARRATIVE BODY (FLEXIBLE COMPONENTS)
# =====================================================================
# OBJECTIVE: Use building blocks that can be rearranged based on skeleton.

Available_Components:
  1. **Zero-Click Summary**: `> Blockquote` at top. Vary template:
     - Template A: "[Topic] is [feasibility] for [scenario]. Key consideration: [trade-off]."
     - Template B: "While [benefit] is achievable, engineers must account for [critical factor]."
     - Template C: "Our experience shows [insight]. Here's what it takes to succeed."

  2. **The Hook**: Start with:
     - A common dilemma (most frequent)
     - A surprising failure
     - A cost paradox
     - A technical myth

  3. **The Analysis**: Mix formats:
     - Physics-first explanation
     - Manufacturing constraints breakdown
     - Economic analysis
     - Risk assessment

  4. **The Execution Log**: Share a case study but vary framing:
     - "Project X: What Went Wrong"
     - "How We Achieved Y Despite Z"
     - "The True Cost of Perfection"

  5. **Data Presentation**: Choose ONE format:
     - Markdown table
     - Bullet comparison
     - Pro/Cons list
     - Parameter matrix

  6. **Verdict System**: Use traffic lights but vary presentation:
     - Simple: 🟢/🟡/🔴 with conditions
     - Graded: Feasibility Score (7/10)
     - Scenario-based: "Choose if... Avoid if..."

  7. **FAQ**: Use HTML5 `<details>` but vary question types:
     - "How much does it cost?"
     - "What's the lead time?"
     - "What are the alternatives?"
     - "What's the most common mistake?"

  8. **Readiness Check**: Place before FAQ or after verdict, vary questions.

  9. **Visual Placeholders**: Insert **[Figure X]** where needed.

Component_Assembly_Rule:
  - Follow selected skeleton's flow.
  - Include at least 5 of the 9 components.
  - Never use components in exact same order as previous article.
